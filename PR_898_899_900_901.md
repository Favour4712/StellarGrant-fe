## fix: checklist reset on resubmission, auto-approve hardening, revoke_role no-op

Closes #898
Closes #899
Closes #900
Closes #901

### Changes

**#898 – stale checklist approval after rejection** (`lib.rs`, `checklist.rs`, `storage/helpers.rs`)
- Added `Storage::remove_checklist_submission` and `checklist::clear_submission`.
- `apply_milestone_submission` clears the checklist submission when a `Rejected` milestone is resubmitted, so `all_required_approved` is `false` until the checklist is resubmitted and re-reviewed.
- Test: `test_resubmission_after_rejection_clears_checklist_approval` (submit → approve → reject → resubmit → not approved → resubmit checklist → re-review → approved).

**#899 – auto_approve `set_config` bounds** (`auto_approve.rs`)
- `set_config` now returns `InvalidInput` whenever `min_votes_required == 0` (previously only when both it and `grace_period_seconds` were 0).
- `grace_period_seconds == 0` is still allowed (e.g. milestones without a deadline).
- Tests: rejects zero votes (even with a grace period), accepts a positive value.

**#900 – auto_approve ignores grant status** (`auto_approve.rs`)
- `try_auto_approve` returns `InvalidState` if the grant is not `Active`; `can_auto_approve` returns `false`.
- Test: a submitted milestone on a cancelled grant can no longer be auto-approved.

**#901 – `revoke_role` no-op emits `RoleRevoked`** (`access_control.rs`)
- `revoke_role` returns `InvalidState` (matching `renounce_role`) if the holder does not have the role, so no event is emitted.
- Test: `revoke_role_errors_when_holder_lacks_role` asserts the error and that no events were emitted.
